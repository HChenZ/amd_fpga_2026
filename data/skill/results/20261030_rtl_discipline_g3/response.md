# counter8 设计说明

## 寄存器清单

| 寄存器 | 位宽 | 时钟/复位 | 下一值语义 |
|---|---:|---|---|
| `count` | 8 | `clk` 上升沿；`rst_n` 同步低有效 | 按 `rst_n > clear > load > enable > 保持` 的优先级选择 |

`count` 是本模块唯一状态寄存器；没有额外的流水级、状态机状态或辅助寄存器。`load_data` 是输入数据通路。

## 下一值优先级推导

在每个 `clk` 上升沿，`count` 的下一值按以下顺序选择：

1. `rst_n = 0`：`count <= 8'd0`，同步复位优先于全部控制输入。
2. 否则 `clear = 1`：`count <= 8'd0`，覆盖 `load` 和 `enable`。
3. 否则 `load = 1`：`count <= load_data`，覆盖 `enable`。
4. 否则 `enable = 1`：`count <= count + 8'd1`；`8'hFF + 8'd1` 自然回绕为 `8'h00`。
5. 其余情况：`count <= count`，显式保持当前值。

这对应于一条有优先级的条件选择链。综合目标是单个 8 位寄存器及围绕它的复位/清零、加载、递增和保持选择逻辑。

## 假设

- 使用 Verilog-2001 可综合语法；所有端口位宽和控制语义均按题目定义。
- `rst_n` 仅在 `clk` 上升沿采样，属于同步低有效复位，不要求异步复位行为。
- `clear`、`load`、`enable`、`rst_n` 均为单比特控制信号，不需要同步器；如需跨时钟域使用，应由外部完成时钟域处理。
- 同时有效的控制输入严格遵循题目给定的优先级，不从脉冲宽度或到达顺序推断其他行为。
- `count` 唯一存储元素；每拍都显式写入其下一值，因此不会推断额外锁存器或保持寄存器。

### 定向场景

- 复位优先级：在非零 `count` 下分别与 `clear`、`load`、`enable` 及它们的组合同时有效，确认下一拍 `count == 8'h00`。
- `clear` 与 `load` 同时为 1：使用与当前值不同的 `load_data`，确认结果为 `8'h00`。
- `load` 与 `enable` 同时为 1：确认直接加载指定值而不是执行加一；再用连续多拍验证控制信号保持时持续加载。
- 回绕：从 `8'hFE` 在 `enable = 1` 时验证到 `8'hFF`，下一拍再验证回绕到 `8'h00`。
- 保持：`rst_n = 1` 且 `clear = load = enable = 0` 时，连续多拍确认 `count` 不变。
- 连续加载：连续多拍保持 `rst_n = 1`、`clear = 0`、`load = 1`，每拍更换 `load_data`，确认每拍均接受新值。
- 边界数据：加载 `8'h00`、`8'h01`、`8'h7F`、`8'h80`、`8'hFE`、`8'hFF` 后检查优先级及回绕行为。

### 检查方式

- 每个采样点检查正常控制后的输出，并记录复位、加载、递增和保持的覆盖命中。
- 在时钟上升沿前建立稳定输入，在上升沿后留出传播时间检查 `count`；本设计预期为单周期状态更新。
- 若后续执行仿真，应覆盖全部 16 个控制组合及上述定向场景；本次交付不包含测试平台，也不执行仿真。
