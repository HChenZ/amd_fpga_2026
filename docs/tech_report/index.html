摘要

本作品在正点原子领航者 ZYNQ7020 开发板上实现集成 Ascon-AEAD128 的 RISC-V SoC。 PL 内为五级流水线 RV32IM + Zicsr 处理器，包含分支预测、I/D Cache、AXI 互连及 UART、GPIO、CLINT。密码功能以 NIST SP 800-232 Final 为基准，提供纯软件、存储器映射加速器和定制指令三种方案。四条定制指令使用 custom-0 编码空间，以 inline assembly 调用，不修改 GCC backend。

当前 PYNQ 发布版由 PS 经两个 AXI-Lite 窗口及 PL 内 UART mailbox 控制 RV32 服务固件。明文和关联数据各不超过 16 B，三模式各通过 289 组官方容量内 KAT 及 289 次错误 Tag 拒绝。 Notebook 顺序执行、9 项错误恢复门禁与每模式 50 次加解密往返均已有实板记录。固定官方 KAT #529（PT=16 B、AD=0），各预热 5 次后采样 30 次，加密 SW/HW/ISE 中位周期为 23342/1439/3995，HW 与 ISE 的周期加速比为 16.221×、5.843×；解密为 24005/1388/4385 周期。周期来自固件 AEAD 调用边界，不含 PS 与串口；PS 调用墙钟中位 4.262–5.216 ms 单列，不充作同倍数响应加速。

Vivado 2025.2 对当前 pynq_wrapper 发布版在配置 100 MHz 下实现 WNS +0.034 ns、TNS 0、 setup/hold 失败端点 0、DRC 0 Error/0 Critical Warning，普通 Warning 如实保留。另实现独立的 256 路 RO-PUF 与 Device DNA 密钥通路原型，同次上电的注册/重建自检通过，最新有效日志注册质量为 128/128；不声称跨上电稳定、密钥保密隔离或完整安全启动。 host 完整 1089 组 KAT 与板级 289 组分列；独立频率、小时级稳定性与干净环境端到端复现尚未完成。

关键词：RISC-V；Ascon-AEAD128；定制指令扩展；MMIO；Zynq-7000；PYNQ；RO-PUF 原型

第一部分 作品概述

1.1 功能与特性

本作品在 Zynq-7020 上实现 RV32/PYNQ 短消息认证加密平台。PL 内为五级 RV32IM + Zicsr CPU，提供标准 Ascon-AEAD128 软件、MMIO 与定制指令三种方案。当前 PT/AD 各 ≤16 B，key/nonce/tag 各 16 B。 PS 通过两个 AXI-Lite 窗口与 PL 内 UART mailbox 调用 RV32 服务固件，Jupyter 展示正确性、CPU 周期与 PS 墙钟。三模式各 289 组官方容量内 KAT、坏 Tag 拒绝及 9 项错误恢复门禁已有实板记录；完整 1089 组仅为 host 范围，不承诺超容量板级功能。

本作品面向资源受限嵌入式设备的短消息认证加密，选择 NIST SP 800-232 Final Ascon-AEAD128，在既有五级流水线 RISC-V CPU 上比较纯软件与两条硬件加速路径。算法公开参考实现与官方 KAT 提供独立正确性基准；可交互 PYNQ 演示提供调用、验证与性能展示入口。

本次交付聚焦标准正确性、同平台周期对照、可运行 overlay 与可追溯证据。 host 执行完整 1089 组 KAT；板端只声明容量内 289 组及负向验证，未验收项见 §3.3.5。

1.2 应用领域

本作品面向资源受限嵌入式系统的短消息认证加密评估，例如传感器状态、控制消息或设备间小包数据。当前实测只证明开发板上的有限长度功能与性能，不等于已部署产品的安全认证。

平台也可作为体系结构与 FPGA 实验载体：同一 RV32 上比较纯软件、CPU 驱动 MMIO 与定制指令，用相同向量和测量边界观察周期差异。替换算法或平台需重新适配验证，不能直接沿用本作品性能值。

1.3 主要技术特点

三方案同平台、同输入对照；custom-0 的四条定制指令以 .insn 调用，不修改 GCC backend； AEAD 密文和 Tag 与锁定 Final 参考逐字节比对；CPU mcycle 与 PS 墙钟分别保存。构建采用 Vivado 2025.2，bit/hwh/固件逐项记录哈希；仿真、板测、实现报告与未测项分层标注。当前 PYNQ 数据通道为 AXI-Lite 字节 FIFO 与 RV32 uncached UART，不使用共享可缓存数据缓冲。

数据通路的关键接口约定如下：

  • 指令与数据的地址空间由 Cache 区分：I-cache 与 D-cache 独立查询同一片 BRAM 区域（统一编址， > 0x1000_0000 起 128 KiB）；不可 Cache 的访问（MMIO）直接经总线完成，不进入 Cache；
  • 结果类型于 ID 级判定：指令在译码阶段即标注结果来源（算术、逻辑、移位、load、跳转链接、乘法）， EX 级据此选择数据通路，避免在执行级重复译码；
  • 旁路于 ID 级选路、于 EX 入口生效：优先级为 EX/MEM > MEM/WB（bypass.v 中两级 MUX）； load-use 冒险以停顿方式解决，不采用推测加重放；
  • CSR 读写置于 EX 级：mepc、mcause、mtvec 与陷入入口位于同一路径，使 ecall 与 mret 的 PC 修复仅有单一实现。

2.2 处理器架构与设计思路

2.2.1 设计目标与总体思路

处理器以 CICC1000023 作品中的自研 RV32 五级流水 CPU 为基础，本作品不重新设计 CPU，而是在其上完成器件迁移、时序改造与密码加速扩展。设计围绕三个目标展开：

  1. 在 XC7Z020 上以 100 MHz 稳定运行。7020 的 LUT 与布线资源有限，结构选择优先考虑时序可收敛，而不是追求更高的单线程性能。
  2. 为三种 Ascon 实现提供公平的对照平台。软件、MMIO 与定制指令必须运行在同一 CPU、同一存储层次、同一测量方式（mcycle）下，周期差异才只来自实现方式本身。
  3. 让定制指令接入后不破坏既有流水线语义。新增指令要能被停顿、被陷入取消，且不会因停顿而重复执行。

据此形成以下设计取舍：

2.2.3 取指单元（IF）

取指级的职责为每周期产生一个 PC 及一条指令，需同时处理 Cache 命中、分支预测与流水线冲刷三项相互耦合的条件。

  • PC 来源优先级（由高至低）：陷入与中断入口、EX 级分支重定向（jump_en）、分支预测目标、 pc + 4；
  • I-cache 查询：容量 1 KiB，64 组 × 4 字/行，直接映射；tag 命中时当拍返回。未命中时进入 FILL 状态并向总线发出一次 burst 请求，ctrl.v 收到 icache_stall 后冻结 IF 与 IF/ID；
  • 预测器接口：取指级以当前 PC 组合读出 pred_taken 与 pred_target（分布式 RAM，零延迟），预测命中时当拍改选 PC，不增加流水级；
  • 冲刷：flush[4] 清除 IF，flush[3] 清除 IF/ID。分支重定向（jump_en）时 ctrl.v 置 flush[3:2]（清除 IF/ID 与 ID/EX 两级，作废两条较年轻指令）；陷入、mret 与外部中断时置 flush[3:1]（额外清除 EX/MEM）。各级冲刷的流水线代价随清除级数而变，本文不作未经实测的拍数结论。

图 2-3 IF 级数据通路与冲刷语义：PC 选择、I-cache 查询、预测改选、miss FILL 与分支冲刷（flush[3:2] 两级）；为结构示意，不作为实测周期波形。

2.2.4 译码单元（ID）

译码级完成字段解析与指令意图标注，为流水线中控制逻辑最密集的一级。

  • 立即数生成：I、S、B、U、J 五种格式并行生成，由 opcode 选择；
  • 寄存器堆：32 × 32-bit，双读一写；x0 恒为零（写端口屏蔽）；同步写、组合读。读地址与有效写地址相同时直接返回 w_reg_data，存在寄存器堆内部写读旁路，并非返回旧值；
  • 结果类型（ResultKind）：将指令映射为六类结果来源（算术、逻辑、移位、load、跳转链接、乘法），该标注随流水线传递至 EX/MEM/WB，为后级"不再重复译码"的基础；
  • CSR 指令与陷入：csrrw、csrrs、csrrc、ecall 与 mret 于 ID 级识别为 SYSTEM 类，具体读写与 mepc、mcause 更新在 EX 级完成；
  • load-use 检测：ID 级比较 id_ex.rd 与当前 rs1、rs2，命中时置 stall_ld，由 ctrl.v 冻结 IF 与 IF/ID（stall[4:3]），并在 ID/EX 插入气泡（flush[2]）；EX/MEM 不再清除。

2.2.5 执行单元（EX）

执行级为多功能并行与多周期串行相结合的混合结构，本作品的两处关键改造均作用于该级。

并行功能单元：ALU（加、减、逻辑、比较、移位）、分支条件判定、跳转链接地址生成与 CSR 读写均在单周期内完成；乘法器 mult.v 完成 32 × 32 有符号与无符号乘法（RV32M 的 mul、mulh、mulhsu、mulhu），综合后被映射为 4 个 DSP48E1（实现报告 DSP 利用率 4／220），映射结果由工具的乘法推断产生而非显式例化 DSP 原语；除法器 divider.v 为迭代式多周期实现（div、divu、rem、remu）。

多周期与握手：执行级向 ctrl.v 发出 ex_stall_req，后者冻结 IF、IF/ID 与 ID/EX 并在 EX/MEM 插入气泡。多周期单元完成时将结果与 done 一并锁存，直至被确认（ack）方予释放。乘法器于本轮改造中增加 mul_ack 与 cancel 两个内部端口，其契约为：输入寄存器至乘积寄存器，接受后下一拍乘积与 mul_done 有效；done 与结果保持至 ack；cancel 或 reset 取消且不产生完成信号。该契约使"乘法结果在 EX 级保持"与"陷入取消"两项行为互不干扰。

Ascon ISE 接入点：custom-0（opcode 0x0b，funct7 = 0，funct3 区分四类操作）在该级被识别为一类带状态的多周期指令，其读写对象为 ISE 内部的 10 个 32-bit 状态字（§2.3.3.4），而非通用寄存器。执行级以 hold 方式使流水线跨越 P12/P8 的多拍执行，done 保持至指令推进；"完成有效方予退休"的判据保证该指令不会因跨过完成的停顿而被重复执行。

图 2-4 EX 级功能单元与多周期握手状态图：含 `Idle → Busy → Done → ack 转换、陷入与中断取消分支，以及 ISE hold 与 ALU 单拍路径的复用关系。

2.2.6 访存与写回（MEM/WB）及 Cache 结构

访存级将执行级的地址与数据转换为 D-cache 事务或总线事务；写回级完成 GPR 与 CSR 写回。

D-cache 结构（dcache.v）：容量 2 KiB，64 组 × 4 字/行，两路组相联，采用 write-through 策略（store 不等待填充），tag 与数据分存；不可 Cache 的地址（MMIO 窗口）绕过 Cache，改为单拍注册请求。状态机为 IDLE / MISS_CAPTURE / FILL 三态：

  • IDLE：查询 tag，命中即返回；
  • MISS_CAPTURE：本轮新增状态，将 miss 的 tag、index、way 及请求属性锁存一拍，使"miss 判定至总线请求"不再经过单一长组合路径；
  • FILL：等待总线填充完成，逐字写入 way。

I-cache：容量 1 KiB，64 组 × 4 字/行，直接映射，状态机为 IDLE/FILL 两态，未命中时整行填充。

写回：mem_wb 选择访存结果、load 数据、PC + 4 或 CSR 读值，驱动 regfile 写口；x0 于写口屏蔽， "读 x0 恒为零"由寄存器堆本身保证，写回级不再作特判。

2.2.7 CSR、异常与计数

csr_file.v 实现的 CSR 集合为：mstatus（0x300）、misa（0x301）、mie（0x304）、mtvec（0x305）、 mscratch（0x340）、mepc（0x341）、mcause（0x342）、mtval（0x343）、mip（0x344）、 mvendorid（0xF11）、marchid（0xF12）、mimpid（0xF13）、mhartid（0xF14），以及 64-bit mcycle 与 mcycleh（0xB00／0xB80）。其中 mvendorid／marchid／mimpid／mhartid 返回常量 0。

  • mcycle 为唯一周期来源：每个非复位时钟加一，RV32 经 0xb00（低）与 0xb80（高）访问，软件按 high→low→high 顺序读取并校验一致性后重读。本作品全部周期加速比均以 mcycle 差值计算，不以事件计数之和替代——后者（cpi_cnt 的 inst、stall、flush 事件）存在重叠，不可相加为周期数；
  • 陷入流程：ecall 于 EX 级写入 mepc（当前 PC）与 mcause = 11，跳转至 mtvec；mret 自 mepc 恢复 PC；外部中断经 ireq_external = gpio_irq | uart_irq | ascon_irq 汇聚，抢占时由 stall_ctrl 清除较年轻指令；
  • 计数与 CPI：cpi_cnt.v 挂接 0x6000_0000 窗口，提供 probe_inst_valid、probe_stall_ld、 probe_stall_md 与 probe_flush_br（每事件计权 2）四组 64-bit 计数；CPI 以同一区间的 cycle delta 与已退休指令 delta 计算，不采用事件加权和。

2.2.8 分支预测

预测器为 64 项单表结构（branch_predictor.v，INDEX_WIDTH = 6）：

  • 表项：tag 表、BTB 目标表（分布式 RAM，ram_style="distributed"，整体 dont_touch）、2-bit 饱和计数器 BHT 与打包 valid 向量；
  • 索引：index = pc[7:2]（指令 4 字节对齐，低 2 位恒为零），tag = pc[31:8]；
  • 预测：仅当 valid && tag_match && bht >= 2'b10 时判为 taken，目标取 BTB 中记录的历史目标；
  • 更新：分支进入 EX 级后训练（update_en、pc_ex、actual_taken、actual_target），并按 2-bit 状态机更新 BHT（00↔︎01↔︎10↔︎11，初值为弱不跳）。误预测冲刷由 ctrl.v 统一处理，预测器不参与冲刷。

采用"小型表 + 分布式 RAM"而非大容量 BTB，系针对本平台的容量与时序折衷：在 100 MHz、LUT 资源受限的 7020 器件上，该结构的面积与时序代价均较低；就本 SoC 的主要负载（AEAD 分块循环与基准测试主循环）而言，其命中率与单独性能贡献尚未量化，本文不以结构描述替代实测结论。

2.3.3.1 算法标准与参数定义

Ascon 的安全核心为 320 bit 状态 \(S=(s_0,s_1,s_2,s_3,s_4)\)，每个分量 64 bit，认证加密通过"吸收与挤出＋置换"实现。AEAD128 的参数如下表。

表 2-6 Ascon-AEAD128 参数

参数 取值 本作品的处理
key 16 byte / 128 bit \(K_0\) 取低 64 bit，\(K_1\) 取高 64 bit
nonce 16 byte / 128 bit \(N_0\)、\(N_1\) 同理
tag 16 byte / 128 bit 完整输出，不截断
rate / capacity 128 bit / 192 bit 每块吸收 16 byte
初始向量 整数 0x0000_1000_808c_0001，字节串 01 00 8c 80 00 10 00 00 常量以位移式匹配
轮常量 f0 e1 d2 c3 b4 a5 96 87 78 69 5a 4b（第 0 至 11 轮） P12 取前 12 个，P8 取后 8 个
域分离 \(s_4 \mathrel{\oplus}= 2^{63}\)（0x8000_0000_0000_0000） 于 AD 与 PT 之间插入

轮函数。第 \(i\) 轮先执行常量加与 S-box，再执行线性扩散：

\[ \begin{aligned} s_2 &\mathrel{\oplus}= c_i \\ s_0 &\mathrel{\oplus}= s_4,\quad s_4 \mathrel{\oplus}= s_3,\quad s_2 \mathrel{\oplus}= s_1 \\ t_0 &= \overline{s_0}\, s_1,\;\; t_1 = \overline{s_1}\, s_2,\;\; t_2 = \overline{s_2}\, s_3,\;\; t_3 = \overline{s_3}\, s_4,\;\; t_4 = \overline{s_4}\, s_0 \\ s_0 &\mathrel{\oplus}= t_1,\quad s_1 \mathrel{\oplus}= t_2,\quad s_2 \mathrel{\oplus}= t_3,\quad s_3 \mathrel{\oplus}= t_4,\quad s_4 \mathrel{\oplus}= t_0 \\ s_1 &\mathrel{\oplus}= s_0,\quad s_0 \mathrel{\oplus}= s_4,\quad s_3 \mathrel{\oplus}= s_2,\quad s_2 = \overline{s_2} \end{aligned} \]

线性层（\(\mathrm{rotr}\) 表示 64 bit 循环右移）：

\[ s_i \mathrel{\oplus}= \mathrm{rotr}(s_i,\,r_{i,1}) \mathrel{\oplus} \mathrm{rotr}(s_i,\,r_{i,2}), \qquad (r_{i,1},r_{i,2}) \in \{(19,28),(61,39),(1,6),(10,17),(7,41)\} \]

AEAD 流程（加密方向）：

  1. 初始化：\(S \gets (IV,K_0,K_1,N_0,N_1)\)，\(S \gets P^{12}(S)\)，\(s_3 \mathrel{\oplus}= K_0\)， \(s_4 \mathrel{\oplus}= K_1\)；
  2. 关联数据：按 16 byte 分块吸收并执行 \(P^8\)；非空整块之后仍须追加一个空 padding 块并再次执行 \(P^8\)；
  3. 域分离：\(s_4 \mathrel{\oplus}= 2^{63}\)；
  4. 明文：按 16 byte 分块挤出 \(C_i = P_i \oplus (s_0 \| s_1)\) 并执行 \(P^8\)；末块不足 16 byte 时先补 0x01 再补 0x00，末块不再置换；
  5. 终结：\(s_2 \mathrel{\oplus}= K_0\)，\(s_3 \mathrel{\oplus}= K_1\)，\(S \gets P^{12}(S)\)， \(s_3 \mathrel{\oplus}= K_0\)，\(s_4 \mathrel{\oplus}= K_1\)；
  6. 标签：\(T = \mathrm{LE64}(s_3) \,\|\, \mathrm{LE64}(s_4)\)；密文与明文等长。

三种方案遵循的实现要点如下。完整 1,089 组 KAT 为 host 验证范围；当前板级三模式仅验证容量内 289 组：

  • padding 为"追加字节 0x01 后补 0x00"，在 64-bit 字中表示为 \(1 \ll (8n)\)，\(n<8\)；
  • AD 为空时既不吸收亦不 padding，但仍执行域分离；
  • 整块 AD 与整块 PT 之后均须再经一个空 padding 块，不得以"满块即结束"处理；
  • 长度须显式给出，不得由"最高非零 bit"反推（否则 00 与 a500 将判定错误）。

图 2-7 Ascon 置换数据通路：5 × 64-bit 状态、S-box 的五个与非项组合、线性层的五组双旋转与轮常量注入；标注 P12/P8 轮数差异及 ISE 内 320-bit 状态寄存器位置。

2.3.3.2 方案一：纯软件实现（SW）

软件实现为正确性基准，同时作为周期加速比的参照基准（分母）。生产代码位于 ascon/ascon_c/aead/，锁定且不可修改的参考实现位于 sim/ascon/reference/ascon_c/（ascon-c 固定 commit 446347f2）。

API 契约（C）：

  • crypto_aead_encrypt(c, clen, m, mlen, ad, adlen, nsec, npub, k)：clen 含 16 byte tag；
  • crypto_aead_decrypt(m, mlen, nsec, c, clen, ad, adlen, npub, k)：tag 拼接于密文末尾，成功返回 0，且 *mlen = clen − 16；认证失败返回 −1，*mlen = 0，并清除 m[0, clen−16) 范围内的候选明文；clen < 16 时返回 −1 且不写 m。

"认证失败须清除候选明文"为项目验收要求，非 SUPERCOP 的强制项：原始 C 参考在 bad tag 时返回 −1，但缓冲区仍保留明文，且 mlen 等于明文长度。本作品修复生产 C 实现的失败处理，并将"原始 C 的真实 FAIL 行为"作为保留证据，不予掩盖。

历史 PL-only 构建：以 xpack riscv-none-elf-gcc 15.2.0、-O2 交叉编译为裸机固件，链接至 0x1000_0000，经 UART 输出测试结果。周期加速比的分母即该固件在板上的 mcycle 增量。在 16 字节明文、 warm 条件（指令已在 I-cache）下，板上实测为 20806 周期。当前 PYNQ 服务固件的固定输入加密中位周期为 23342，见 §3.3.4.1；不与历史工具链和测量边界混用。

2.3.3.3 方案二：存储器映射加速器（MMIO／HW）

MMIO 实现将整个 AEAD 实现为挂接于 0x3000_0000 的从设备，CPU 仅承担参数搬运、状态轮询与结果读取。当前接口取自发布源集 board/vivado_zynq7000_xc7z020_pynq/rtl_p0/ascon_mmio.v，如下表。

表 2-7 MMIO 加速器寄存器

偏移 名称 读写 位定义与语义
0x00 CTRL W [0] START（自清脉冲，仅空闲态接受）；[1] ENCRYPT（1 加密，0 解密）；[2] ZEROIZE（仅空闲态接受，同一写中优先于 START）
0x04 STATUS R [0] BUSY；[1] DONE；[2] FAIL（解密 tag 校验失败）
0x08 ADLEN W AD 字节数
0x0C MLEN W 消息字节数
0x10–0x1C KEY W 四个小端序 32-bit key 字，由调用者写入
0x20–0x2C NONCE W \(N_0\) 至 \(N_3\)

0x40 AD_WDATA W 推入一个 AD 字（内部指针自增）
0x44 MSG_WDATA W 推入一个消息字（加密为明文，解密为密文）
0x48 OUT_RDATA R 弹出一个输出字（加密为密文，解密为明文），指针自增
0x4C–0x58 TAGOUT R 加密计算所得 tag

以下四项行为构成"可用外设"而非"可计算模块"的判据，须写入契约：

  1. BUSY 期间全部写操作被忽略，包括 ZEROIZE、START、key/nonce、长度与输入缓冲；
  2. 输出读门禁：OUT_RDATA 仅在 DONE && !BUSY && !FAIL 且未超出有效字数时返回数据并推进指针，其余情形返回零且不推进。认证失败不得发布明文由硬件保证，不依赖软件自觉；
  3. ZEROIZE：清除 key、nonce、tagin、长度与状态，以及全部 AD、MSG、OUT 数组，并经子核心复位清除适配器缓冲、\(s_0..s_4\)、候选明文与 P8/P12 私有副本。DONE 本身不等于清理，取完结果后须显式清零；
  4. 长度上限：硬件实际支持 AD 与消息各 0 至 16 byte（参数名 MAX_AD_BYTES=256 仅为缓冲上限，不代表多块能力），超长请求显式返回 FAIL。该限制为 P0 的边界条件：板级 MMIO 周期加速比仅对 ≤16 byte 成立，正文不将其泛化为"任意长度"。

延迟结构上，MMIO 端到端周期由参数搬运（key、nonce、AD 与消息的逐字写入）、轮询往返与密码核本体三部分组成。历史 PL-only 16 B 调用为 688 周期，核本体观测 103 周期；当前 PYNQ 固定输入加密为 1439 周期。核外开销的历史分解不直接套用到当前调用。

2.3.3.4 方案三：定制指令扩展（ISE）

ISE 将置换并入 CPU：320 bit Ascon 状态作为执行级的专用寄存器堆，由 4 条定制指令访问。指令占用 RISC-V 预留的 custom-0 编码（0b0001011），未新造主操作码值，4 条指令以 funct3 区分。

表 2-8 定制指令编码与语义

funct3 助记符 操作数 周期 语义
000 ascon.w rs1 为数据，rs2[3:0] 为索引 1 state[32*idx +: 32] = rs1
001 ascon.rd rs1[3:0] 为索引，rd 为结果 1 rd = state[32*idx +: 32]
010 ascon.p12 — 多周期 state = P12(state)
011 ascon.p8 — 多周期 state = P8(state)

状态映射固定为 10 个 32-bit 字：s0 低与高、s1 低与高，直至 s4。非法索引（不在 0 至 9 范围）读返回零、写被忽略；该行为属显式容错约定，不产生非法指令异常。保留 opcode 与 funct 编码的全局审计仍在待办之列，正文不声称已覆盖全部指令空间。

实现细节与生命周期如下：

  • perm_start 为电平信号（指令位于 EX 且未完成期间保持有效），内部状态机对其打一拍脉冲，完成后锁存结果；据此，流水线 hold 跨越完成不会导致重复执行；
  • 取消：陷入与中断经 cancel 丢弃在飞操作并清零 ISE 状态，且不发布迟到结果；普通分支冲刷仅清除较年轻指令，不影响已完成的置换；
  • 局部复位寄存器化：P12/P8 的 1280-bit 私有复位扇出原挂接于全局复位的组合锥（93 个失败端点、 −0.128 ns），改为"取消当拍清架构 state，下一拍清私有 s_reg/s_out"，接受与 p_start 同拍释放局部复位，不增加正常执行的置换周期（§3.3.1）；
  • 无上下文保存与恢复 ABI：陷入取消后不可自中间轮续算，调用者须串行独占或整体重算。当前 bare-metal 自测不启用抢占，真实中断、多任务与嵌套调用下的恢复尚未验证；
  • 软件封装：以 asm volatile 手写 intrinsic（不改动 GCC backend），逐字读写状态并调用 P8/P12；软件侧 AEAD 循环与 MMIO 版本共用同一调用顺序与测试向量，故两版密文与 tag 可逐字节比对。

历史 PL-only 16 B 加密为 2570 周期、相对同组软件 8.10×；当前 PYNQ 固定输入为 3995 周期、相对当前 SW 5.843×。ISE 的设计动机是用硬件置换替代软件轮函数；不同固件的差值尚未完成分项归因，不把推测写成已测结论。

表 2-13 服务帧类型

帧 长度 方向 用途

服务固件 pynq-svc-v1（src/firmware/pynq_svc/）具备以下设计特征：

  • 单槽串行：一次仅处理一个请求，响应发完后回到帧同步状态，故 PS 侧无需额外 ACK 线；
  • 周期口径：仅在 AEAD 调用边界读取 64-bit mcycle（0xB00/0xB80，hi-lo-hi 一致读取），不含串口传输时间；
  • 能力上限：message 与 AD 各 16 字节，超长请求立即拒绝并返回 LENGTH；
  • 构建：src/firmware/pynq_svc/build.sh 以 RV32IM_Zicsr/ilp32 交叉编译，产物中检出 24 条 custom-0 指令，P12/P8 均存在，可作为"ISE 确实被调用"的静态证据；
  • 异常处置：半帧读取依赖主机超时后 reset；无本地接收超时；UART 无远端流控。

2.3.4 独立扩展原型：RO-PUF 与器件绑定通路

本章保留已实现的进阶探索，范围为独立 PL-only 扩展原型，不属于当前 PYNQ release。其成果是 RO 采样、注册、重建判定、派生和内部接线的功能链，不宣称已经完成产品级硬件信任根或安全启动。

2.3.4.1 架构与已实现代码

2.4.2 软件各模块介绍

2.4.2.1 纯软件 AEAD 固件

纯软件路径调用生产 ascon/ascon_c/aead 的 crypto_aead_encrypt/decrypt，按 Final 参数完成初始化、AD 吸收、域分离、消息处理与终结。tag 采用完整 16 B。解密输入是密文与 tag 拼接，认证失败返回失败、输出长度归零并擦除候选明文。锁定上游参考不改；生产失败处理与原参考失败分别保留证据。

当前服务对 PT/AD 统一限制为 16 B；host 完整 KAT 与板级容量内 KAT 分列。固定 #529 的当前 warm 加密中位为 23342 cycles，历史 PL-only 20806 cycles 仅作独立对照。

2.4.2.2 MMIO 加速器驱动固件

MMIO 驱动使用 0x30000000 寄存器窗口：写 KEY(+0x10–1C)、NONCE(+0x20–2C)、 ADLEN/MLEN，推入 AD_WDATA(+0x40)/MSG_WDATA(+0x44)，写 CTRL 启动，轮询 STATUS，读取 OUT_RDATA(+0x48) 与 TAGOUT(+0x4C–58)，结束后显式清零。消息与 AD 各 ≤16 B，BUSY 写忽略，认证成功且在有效长度内才允许输出。

当前 #529 加密中位 1439 cycles，解密 1388 cycles；两者包含驱动调用内搬运与轮询，不含 PS/UART。 HW 轮询异常当前可能表现为 INTERNAL 或认证失败，不能声称存在独立 TIMEOUT 状态码；异常后整链恢复。历史 688 cycles 与核本体 103 cycles 不替代当前服务测量。

2.4.2.3 定制指令固件

ISE 用 ascon.w/ascon.rd 访问 10 个 32-bit 状态字，以 ascon.p12/ascon.p8 执行置换。主操作码 0x0B、funct7=0、funct3=0/1/2/3；inline assembly 使用 .insn，未修改 GCC backend。构建归档检出 24 条 custom-0 静态编码；真实服务运行 KAT 提供动态正确性证据。

当前 #529 加密为 3995 cycles，相对 SW 为 5.843×；历史 PL-only 2570 cycles/8.10× 单列。取消与 hold 的定向测试通过，不据此声称完整中断/抢占上下文保存恢复已验收。

2.4.2.4 当前 benchmark 与采样工具

board_benchmark.py 对同一 release 完成身份检查、三模式 smoke 和固定输入采样。官方 KAT #529、每模式预热 5 次，每操作 30 次，逐次核对 CT/tag/PT，并保存 raw_cycles/raw_wall_ns。 JSON 同时记录服务标志、发布哈希、测量范围和统计；错误结果不能混入成功性能统计。

周期来自 RV32 mcycle 的高低高一致读取。PS 端墙钟独立计量，不以事件计数器相加代替总周期，也不将 CPU 周期加速比称为 PS 响应加速比。当前结果目录为 data/pynq/notebook_20261029_130920/。

2.4.2.5 PS 端服务与帧协议

服务固件按 magic 识别 Y01E/Y01Q，校验 version、flags、epoch、request_id、mode、operation 与长度，按 mode 调度三种实现，发送 Y01R；Y01S 发送固件身份、自检与 epoch 应答。当前帧没有 CRC 字段。请求/响应头各 48 B，Y01S 为 64 B，Y01E 为 20 B；失败响应无 payload/cycles。

超时不自动重传，须主机 reset/recover、更新 epoch 并重新验证 KAT。重复 ID 与错误 epoch 返回 INTERNAL；PT/AD >16 B 返回 LENGTH。半帧与 FIFO overflow 后恢复已板测；服务端无本地半帧接收超时，单客户端无跨进程锁。 9/9 错误门禁与每模式 50 次往返有 JSON/log/已执行 Notebook 证据，非小时级验证。

第三部分 完成情况及性能参数

3.3.3.2 L0：标准一致性与向量冻结

该层的作用是将标准固化为不可变的字节序列，作为 RTL 与板级验证的唯一参照。

  • 标准版本：NIST SP 800-232 Final（2025-08-13 发布），本地 PDF 哈希 1be9bb9a…。旧版 Ascon v1.2 的 Ascon-128 与 Ascon-128a 在端序、IV 与 padding 上均不同，不可沿用其 KAT；
  • 参考实现：ascon-c 固定 commit 446347f2（上游 crypto_aead/asconaead128/ref/）与 pyascon 固定 commit ed24e54a。pyascon 的 README 仍标注 draft，故"是否对应 Final"不以文档表述判定，而以 "通过完整官方 KAT"为判据；
  • 官方向量：LWC_AEAD_KAT_128_128.txt（同 commit），共 1,089 组，即 PT 与 AD 长度在 0 至 32 的笛卡尔积，哈希 bbbc3469…。key、nonce、PT、AD 与 expected CT 均取自原始文件，未使用本仓库生成器自证；
  • 扩展向量：aead_cases.json 共 64 组，其中 54 组取自上游矩阵，10 组为锁定 C 参考的扩展用例（含空串、a5 与 a500、尾零、33/64/129-byte PT 及最长 81-byte AD），每组附带首、尾 CT 与 tag 翻转输入；
  • 置换向量：22 个输入状态 ×（12 个单轮、P8、P12），共 308 组，源自锁定 C helper，并经 Python 二次校核；
  • 冻结机制：freeze_vectors.py 先令两个锁定参考通过完整独立下载的 KAT，再由锁定 C 参考产生扩展用例、由 Python 交叉检查；仅写入新建空目录，不覆写上游 KAT；两次重生成的三个数据文件字节完全一致。

第四部分 总结

4.1 可扩展之处

以下方向均未实施，属后续计划，不计入本轮成果。

  1. 长消息支持：当前 PT/AD 各 ≤16 B，经 AXI-Lite 字节 FIFO 传输；可改为共享缓冲或流式搬运，并补齐完整 1089 组板级 KAT 与多块吞吐测量。
  2. 器件绑定密钥：将独立 RO-PUF/Device DNA 原型并入当前 overlay，关闭派生输入回读通路，补充跨上电、温压与多器件统计后再评估密钥用途。
  3. 指令与算法：在现有 custom-0 状态指令上扩展 SP 800-232 中的 Ascon-Hash256/XOF128，并以 intrinsic 封装降低软件调用开销。
  4. 工程验证：补独立频率测量、小时级稳定性、完整 ISA/异常矩阵与干净环境复现。

4.2 心得体会

实现可运行与结论可复核是不同目标。标准 KAT、真实 CPU 仿真与实板测试各自覆盖不同问题，不能用某一层通过替代另一层验收；相同文件名也不能证明工件属于同一构建。因此，发布身份、逐文件哈希、source_dirty 和源集选择应与原始样本一并保存。

性能比较首先是测量边界的比较。当前固定 16 B 输入下 MMIO 与 ISE 均降低了固件调用周期，但 PS 侧调用仍包含 Python 与通信开销，响应时间没有获得同倍数改善。保留这一区别，比仅展示最大的周期加速比更有解释力。

验证框架同样需要负向用例。错误长度、过期 epoch、重复请求及 FIFO overflow 的拒绝与恢复，为演示链的健壮性提供了有限但可复查的证据；它们不构成无限时稳定性、完整 ISA 合规或安全认证证明。报告应保留已知失败与未测项，不以文字更新代替工程验证。

设计准则与证据分级

接口先于实现；未测量项不填零、不计为通过。分别记录 hardware_measured、simulation、 implementation_report 与 not_measured。正 WNS 只说明该 run 在给定约束下通过，不等于最大频率或跨温压稳定性。相同模块源文件不等于共享一个硬件实例；全 SoC 资源不充作某一加速通路的独立面积。

当前 release 的 bit/hwh/固件由 manifest 与逐文件哈希对应。板端 Git、release source commit 和历史仿真 source_head 分别记录，不能视为同一个身份。构建记录 source_dirty=true，因此重建须结合 source_sha256、源集选择与构建输入，不能只 checkout 单个 commit 即宣称可复现。
