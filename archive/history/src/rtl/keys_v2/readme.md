## Build and ports

Exact source order and test tops: `sim/keys_v2/sources.json`. Parse all listed RTL
as SystemVerilog; include directory `src/rtl/ascon`. `crypto_aead.v` includes
permutation/round/word files itself. Do not add those include files a second time.

| Module | Contract |
|---|---|
| `ro_counter_v2` | `osc,rst_n,phase[1:0]` in; `ack[1:0],count[CW-1:0],overflow` out. Asynchronous reset, synchronized phase. Saturating counter, sticky overflow. |
| `ro_puf_core_v2` | `clk,ro_clk,rst_n,start,osc[2*BITS-1:0]` in; `raw[BITS-1:0],valid,done,busy,error_code[7:0],locked,transaction_id[31:0]` out. Diagnostic flattened counts `[2*BITS*CW-1:0]`, counter i at `[i*CW+:CW]`. |
| `puf_key_v2` | `clk,ro_clk,rst_n,clear,start,enroll,osc[255:0],board_dna[56:0],helper_load,helper_ref_in[127:0],helper_mask_in[127:0]` in. Diagnostic `helper_ref,helper_mask`, internal-consumer `key[127:0]`, status `key_valid,busy,done,enrolled,error_code[7:0],quality[7:0],sample_error[7:0],transaction_id[31:0]` out. |
| `puf_aead_v2` | Same key-control inputs (named `key_start`), no key/helper/raw/DNA debug outputs. Status `key_ready,key_busy,key_done,key_error[7:0]`. AEAD inputs `start,decrypt,data_in[127:0],ad[127:0],nonce[127:0],tag_in[127:0],datalen[4:0],adlen[4:0]`; outputs `busy,done,success,error_code[7:0],data_out[127:0],tag_out[127:0]`. |
| `ro_array_v2` | Physical LUT ring bank, `en` in, `osc[N-1:0]` out. No behavioral frequency model; TB supplies explicit synthetic oscillators separately. |
| `puf_physical_v2` | `puf_aead_v2` ports minus `osc`; instantiates 256 five-LUT physical rings. Independent synthesis entry. |

`rst_n` is active low. All control inputs except the oscillator clocks are
core-`clk` domain; pulse starts/helper_load for one cycle. `ro_clk` is a real
external management clock, never generated by this RTL. `board_dna` must come
from a trusted DNA reader, be valid before key_start, and is latched at start;
there is no DNA-only mode or implicit fallback. The direct-control wrapper takes
external DNA; the MMIO wrapper instantiates the existing reader. `clear` must be
core-synchronous and held through at least one clk edge;
it asynchronously asserts sampler reset even if ro_clk is stopped. Management
and each oscillator have local two-stage reset-release synchronizers; core reset
release must be clk-synchronous. Integration must review their physical paths.

Default BITS=128, CW=20, WINDOW=1024 ro_clk cycles, RO_DEADLINE=8192 ro_clk
cycles, CORE_DEADLINE=65536 core cycles, SAMPLES=3, MIN_BITS=64. MIN_BITS is an
engineering quality threshold, NOT 64-bit entropy/security. Require BITS>=2,
CW>=2, WINDOW>=1, SAMPLES>=1, 1<=MIN_BITS<=128 and positive deadlines that fit
32 bits. Physical rings require odd STAGES>=3. Deadline budgeting must account
for actual core/management/oscillator ratios and counter width. These defaults
have not been physically tuned.

## Sampling and CDC protocol

Phase sequence is idle `10` -> clear `00` -> count `01` -> stop `11` -> idle `10`.
Each transition changes one bit. Each oscillator synchronizes phase twice;
clear zeroes the counter, count saturates, stop holds data then acknowledges.
Management synchronizes acknowledgements twice, requires ALL clear acknowledgements,
counts WINDOW management cycles, requires ALL stop acknowledgements, and waits an
additional management edge before snapshot. Counts/overflow then stay stable.
Start/completion toggles use three synchronization flops plus a separate history
flop; edge detection uses ONLY stage 3 and its history, never stage 1.
Result/error are bundled stable data before completion crosses to core clk.
The final-stage completion event now captures that payload into core-domain
registers; decoding/publication occurs one core cycle later. Pending capture is
erased on START/reset/deadline. See `cdc_review_20261030.md` for the concrete
CDC-1 repair, reset-merge CDC-10 analysis and parent re-synthesis checks.

This is a protocol design, not CDC/STA signoff. Physical implementation must
constrain phase/ack and snapshot/result bus delay/skew to their stability
windows, audit reset-release paths and actual netlist synchronizers and
256 retained loops, provide actual clock models, and review placement.
No global false paths or invented ideal RO clocks are supplied.

Sampler `done` pulses for success AND failure; `valid` only for success. New
start clears raw immediately. Timeout/health/busy-start failure locks sampler
until clear/reset, preventing delayed completion from reviving an expired key.
Late completion is ignored outside busy. Count diagnostics are management-domain
signals, valid for inspection only after completion and before the next start;
they are not a core-domain MMIO read interface.

Sampler error bitmask: bit0 management watchdog, bit1 core deadline, bit2 zero
count, bit3 equal counts, bit4 saturation, bit5 all comparisons same direction,
bit6 overlapping request or locked request. Any health failure invalidates the
entire sample (conservative choice); ties are not stable 1s. Saturation prevents
wraparound. No success can be fabricated from incomplete windows.

## Key lifecycle and helper

Enrollment samples SAMPLES times; reference is first sample, mask retains bits
identical in all samples. Reconstruction requires every selected bit to be
stable and equal to imported/enrolled reference. There is NO ECC or correction.
`quality` counts selected bits, not entropy. Zero/insufficient mask fails closed.
`key_valid` is a level, revoked on every start, helper load, clear, reset, and key
operation failure. Key/candidate material is cleared. `done` is a one-cycle pulse;
errors remain until new control. Starts during busy abort explicitly, never queue.
Sampler reset/clear is required after an aborted sampling operation to guarantee
immediate reuse; otherwise busy/locked sampling is explicitly refused.

Key errors: `81` command overlap, `82` missing helper, `83` sampler unavailable or
failed (inspect sample_error diagnostically), `84` insufficient quality/reference
mismatch/empty mask, `85` outer deadline or invalid state. transaction_id increments
on each start/helper_load attempt; clear preserves its value. Helper and enrolled
status survive clear, but full rst_n clears them. Failed new enrollment invalidates
old helper. Existing helper may survive failed reconstruction for explicit retry.

Experimental mapping is `P12({64'h5055465f56325f44,64'h4941474e4f535449,
128-bit(masked response),7'b0,57-bit DNA})[127:0]`. It is deliberately labeled
diagnostic, NOT HKDF/Ascon-XOF or a proven extractor. REF persistence reveals all
selected response bits and permits recomputation; disabling readback on the normal
wrapper does not retroactively make this enrollment scheme secret.

`puf_helper_v2.py` atomically persists strict version-2 JSON with board_id,
build SHA-256, sampling parameters, full reference/mask, and canonical-payload
SHA-256. Binding is checked against caller-supplied expected configuration.
Checksum is accidental-corruption detection, not authentication or rollback defense.
Provisioning inputs are trusted by this prototype; no runtime authenticated
enrollment window or secure loader is claimed. The independent MMIO map is now
specified in `mmio_abi.md`.

## AEAD boundary

Internal key drives existing `crypto_aead` directly. No software key write or
fallback exists. Input/nonce/tag are latched. Data and AD lengths are each 0..16,
little-endian bytes; decrypt=1. On missing/revoked key, overlapping start, invalid
length, timeout or bad tag: success=0, data_out=tag_out=0. Outputs remain zero
throughout busy. Success publishes exactly datalen bytes (upper bytes zeroed).
Key control during AEAD cancels operation and resets cipher state; completion
is ignored after abort. Error codes: 1 KEY_NOT_READY/revocation, 2 overlap/length,
3 authentication, 4 cipher deadline. AEAD errors do not themselves destroy a
still-valid key; clear explicitly destroys readiness. AEAD_DEADLINE defaults 512.
