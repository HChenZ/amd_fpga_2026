失败则停止保存 traceback。不要安装最新版 PYNQ 覆盖厂家环境。

3. 加载并核对 HWH/寄存器，在 Jupyter 的一个单元执行：

```python
from pynq import Overlay, MMIO
from pathlib import Path
release = Path('board/vivado_zynq7000_xc7z020_pynq/release').resolve()
ol = Overlay(str(release/'pynq.bit'))
print(ol.ip_dict)
assert ol.is_loaded()
ctl = ol.ip_dict['pynq_ctl_0']; mb = ol.ip_dict['pynq_mbox_0']
assert ctl['phys_addr'] == 0x40000000 and mb['phys_addr'] == 0x40001000
c = MMIO(ctl['phys_addr'],ctl['addr_range'])
b = MMIO(mb['phys_addr'],mb['addr_range'])
print(hex(c.read(8)), c.read(12), hex(b.read(0x1c)))
assert c.read(8)==0x514e5950 and c.read(12)==1 and b.read(0x1c)==0x4d424f58
```

预期两个独立 IP、正确 ID。0xffffffff、全零或访问挂起均失败，不继续写请求。保存 ip_dict、ID 和 bit SHA。MMIO 总线卡死不能由 Python deadline 抢占，必要时断电重启。

4. CLI 执行真实端到端检查（自动重新加载 Overlay、启动 RV32、等待 boot 服务帧、发送 epoch，逐模式执行加密/解密/错误 Tag）。

```sh
set -o pipefail
python3 src/pynq/board_demo.py --out pynq_board_result.json 2>&1 | tee pynq_board_20261028.log
```

默认每模式六个官方 KAT（容量内代表输入）。boot selftest 必须 mask=7；固件标识必须 pynq-svc-v1，模拟标志必须 false。每模式应有 KAT PASS、Tag reject，CT/tag 与官方 corpus 一致。任何异常/超时/错误明文/非零退出都停止，不允许自动切模拟。失败时保存 terminal log；CLI 只有全部成功才写最终 PASS JSON。

5. 完整容量内 KAT：

```sh
python3 src/pynq/board_demo.py --full-kat --out pynq_board_full.json 2>&1 | tee pynq_board_full.log
```

每模式 289 组加密与解密、289 次错误 Tag 拒绝。剩余 800 组因16B容量不执行，不能写1089组硬件PASS。Notebook 入口 `src/pynq/pynq_board_demo.ipynb`，修改第一单元 repo 路径后 Restart Kernel → Run All；不要同时运行 CLI 和 Notebook（共享单槽，无跨进程锁）。

## E. 故障排查与备用

| 现象 | 操作与失败判据 |
|---|---|
| SD不能启动 | 断电核对镜像SHA、Etcher Verify、卡容量、SD启动模式及插卡；保存U-Boot首个错误；不要更改DDR参数碰运气 |
| 串口无输出/乱码 | 确认 USB-UART COM、115200 8N1、PS P5 唯一桥接、12V电源与启动模式；PL-only备用是另一串口跳线选择，不能两套同时接 |
| 无IP | 查PS网口Link灯、网线、路由器租约；串口 `ip link; ip -4 addr; ip route`；未核实静态IP时不要乱改交换网络 |
| Jupyter打不开 | 电脑先确认同网段，再 `curl -I http://<IP>:9090`；板上 `ss -lntp; systemctl --failed`；有SSH不代表9090已启动 |
| Overlay加载失败 | 保存 traceback、`dmesg \| tail -80`；核对bit/hwh同名、SHA、目标part与PYNQ版本；禁止用别的hwh配对 |
| HWH物理地址不符 | 只按同次构建HWH的ip_dict定位；build_profile/validate_overlay必须通过。地址不是CPU内部0x20000000/0x30000000 |
| AXI读取异常 | 先查ID、GP0、FCLK/复位；读挂起需板级重启。厂家FSBL配置和2025.2 hwh解析尚需实板确认 |
| FIFO数据丢失 | RXSTAT bit18溢出、CNT字节数与原始流一起记录；UART两线没有远端反压；单次最大响应80B可放256B FIFO，但启动文本必须及时排空；禁止多个进程并发 |
| RV32服务没起来 | 控制默认保持复位；Transport释放后先等boot服务帧才发epoch。检查svc COE是否烧入、boot mask=7；不可把STAT复位释放当固件ready |
| KAT错误 | 停止性能演示，保存mode/KAT号/expected/actual/源码与bitSHA；优先查源集是否误用带PUF硬件key覆盖的main SoC |
| cycles异常 | 核对64位mcycle证据、同长度/AD/模式、冷暖与编译器；不要把crypto-core计数或Python wall-time替换mcycle |
| 超时/半帧 | 不自动重试旧请求。MailboxBackend recover执行SoC复位、清链路、更换epoch；或重新运行CLI加载Overlay。固件阻塞收半帧的本地超时尚未实现，必须由主机超时后复位；不能继续往旧流追加请求 |
| 真实通信没通 | 明确记录PYNQ链路FAIL/NOT_RUN；保留host模拟展示时必须显式simulated，cycles=NOT_MEASURED；同时走下述原PL-only演示 |

PL-only备用：按 `docs/freeze_checkpoint_20261027.md`、`board/vivado_zynq7000_xc7z020_ascon/readme.md` 使用已经上板验证的三版镜像，P5切PL串口、JTAG加载、115200抓KAT与周期。冻结索引给出三份bit SHA。当前仓库历史三份bit原本只在原构建机build/local，本机检索未发现匹配文件，因此不得声称pull即可取得这三份旧bit：应由持有原文件的队友提供并核对冻结SHA，或在独立副本按冻结源/COE重建（重建属于新产物、需重新验收）。保留原始COE与板级日志；不要用现在带硬件key覆盖的源集无说明地重建任意key KAT。
